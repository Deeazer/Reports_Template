# Интеграция с Yonote

Приложение умеет импортировать проекты из базы знаний **Yonote** (yonote.ru).
Yonote построен на Outline, поэтому используется совместимое с Outline API
(POST-методы `/api/<группа>.<действие>`, авторизация Bearer-токеном, документы
в Markdown).

## Настройка

1. В Yonote откройте **Настройки → API-токены** и создайте персональный токен.
2. В приложении: **Настройки → Интеграция с Yonote**.
   - **Адрес Yonote** — адрес вашего пространства, например `https://cyberbits.yonote.ru`.
   - **API-токен** — вставьте созданный токен (хранится на сервере, в API не отдаётся обратно).
   - Нажмите **Проверить подключение** — должно показать имя пользователя и команду.
   - **Загрузить коллекции** и выберите коллекцию, где ведутся проекты. Сохраните.

Доступ к настройке и импорту есть только у администратора.

## Импорт

**Проекты → Импорт из Yonote** → выберите коллекцию, отметьте нужные документы
и нажмите «Импортировать». Каждый выбранный документ становится отдельным
проектом приложения (с уязвимостями). Импорт всегда создаёт новые проекты.

## Формат ведения проекта в Yonote

Один **документ верхнего уровня** в коллекции = один проект. Заголовок документа
становится названием проекта. Тело документа — Markdown по шаблону ниже.
Разбор устойчив к мелким отличиям: регистр меток не важен, разделитель «:» или
«—», лишние пробелы и отсутствующие поля/разделы допускаются.

```markdown
# Пентест АО «Экопром» 2026        ← заголовок документа = название проекта

## Карточка
- Заказчик: АО «Экопром»
- Реквизиты: ИНН 7701234567, 123456, г. Москва, ул. …
- Период: 01.10.2026 — 20.10.2026
- Виды работ: external, internal, web
- Описание объекта: Корпоративная сеть и веб-портал
- Технологические участки: ЦОД, офис

## Уязвимости

### Обход авторизации панели администратора
- Вид работ: external
- CVSS: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
- Границы: admin.ekoprom.ru
- Инструменты: BurpSuite, nmap
- Обнаружена: 05.09.2026 12:30
- Модели нарушителя: Н1, Н2

**Описание:** Эндпоинт /admin доступен без аутентификации…
**PoC:** 1. Открыть /admin  2. Наблюдать доступ к панели…
**Результаты эксплуатации:** Полный доступ к административной панели…
**Рекомендации:** Включить проверку сессии и ролей…

### SQL-инъекция в поиске
- Вид работ: web
- CVSS: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N
- OWASP: A03
**Описание:** Параметр q уязвим к SQL-инъекции…
**Рекомендации:** Параметризованные запросы…
```

### Поля раздела «Карточка»

| Метка в Yonote | Поле проекта |
|---|---|
| Заказчик (или Клиент) | Наименование Заказчика |
| Реквизиты | Реквизиты Заказчика |
| Описание объекта | Описание объекта (1.1) |
| Технологические участки | Технологические участки (1.3) |
| Период | Начало/окончание периода |
| Виды работ | Виды работ проекта |

**Виды работ** указываются через запятую — ключами (`external`, `internal`,
`web`, `social`, `dos`, `wireless`) или названиями («Внешний пентест»,
«Веб-приложение» и т. п.). Недоступные/нереализованные виды работ отбрасываются.

### Поля уязвимости (`### Заголовок` = название)

| Метка (bullet) | Поле |
|---|---|
| Вид работ | вид работ уязвимости (по умолчанию — первый вид работ проекта) |
| CVSS | вектор CVSS v3.1 (критичность и риск считаются автоматически) |
| Границы | границы |
| Инструменты | инструменты |
| Обнаружена | время обнаружения |
| Модели нарушителя | модели нарушителя |
| OWASP | категория OWASP Top 10 (для веб) |
| WSTG | категория OWASP WSTG (для веб) |

Крупные тексты оформляются «жирными» метками `**Метка:**`, после которых идёт
текст до следующей метки:

| Метка | Поле |
|---|---|
| **Описание:** | описание уязвимости |
| **PoC:** | Proof of Concept |
| **Результаты эксплуатации:** | результаты эксплуатации |
| **Рекомендации:** | рекомендации |

## Что НЕ переносится

Скриншоты и вложения Yonote в текущей версии не импортируются (переносится
только текст). Границы проекта (Приложение 1), нарушители и каталог угроз берутся
из справочников по умолчанию — их можно отредактировать в проекте после импорта.
