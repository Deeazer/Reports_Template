## 1. Требования

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| ОС | Linux x86-64 с Docker; Windows 10/11 или macOS с Docker Desktop | Linux-сервер (Ubuntu 22.04+, Debian 12, Astra Linux, РЕД ОС) |
| ЦП | 2 ядра | 4 ядра |
| ОЗУ | 2 ГБ свободной памяти | 4 ГБ |
| Диск | 3 ГБ (образы) + место под скриншоты | 20 ГБ и больше |
| ПО | Docker Engine 24+ с плагином Docker Compose v2 | последние стабильные версии |
| Сеть | при сборке образов — доступ к Docker Hub и PyPI | см. раздел 10 для закрытого контура |

Приложение использует три контейнера:

| Сервис | Образ | Назначение | Порт |
|---|---|---|---|
| `frontend` | nginx 1.27 | интерфейс, проксирование `/api` | наружу `8080` (настраивается) |
| `backend` | Python 3.12 | API и генерация DOCX | только внутри сети Docker |
| `db` | PostgreSQL 16 | база данных | только внутри сети Docker |

Данные хранятся в двух томах Docker:

| Том | Содержимое |
|---|---|
| `pentest-reports_db_data` | база данных: пользователи, проекты, уязвимости, настройки |
| `pentest-reports_uploads` | загруженные скриншоты |

> Префикс `pentest-reports_` совпадает с именем каталога, из которого
> запускается `docker compose`. Если каталог называется иначе, имена томов
> будут другими. Посмотреть их можно командой `docker volume ls`.

## 2. Установка Docker

### Linux (Ubuntu/Debian)

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # чтобы запускать docker без sudo
# выйдите из системы и войдите снова
docker --version
docker compose version
```

На Astra Linux и РЕД ОС установите Docker из репозитория дистрибутива по
документации производителя ОС.

### Windows

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/).
2. При установке оставьте включённым использование WSL 2.
3. Перезагрузите компьютер и запустите Docker Desktop. Дождитесь статуса
   «Engine running».
4. Проверьте в PowerShell:
   ```powershell
   docker --version
   docker compose version
   ```

### macOS

Установите Docker Desktop для вашего процессора (Apple Silicon или Intel) и
запустите его.

## 3. Получение файлов приложения

Склонируйте репозиторий на сервер, например в `/opt/pentest-reports`:

```bash
git clone https://github.com/Deeazer/Reports_Template.git /opt/pentest-reports
```

Без доступа к GitHub скопируйте каталог проекта на сервер целиком. Структура:

```
pentest-reports/
├── docker-compose.yml
├── .env.example
├── README.md
├── INSTALL.md
├── backend/
└── frontend/
```

Все дальнейшие команды выполняются из этого каталога:

```bash
cd /opt/pentest-reports
```

## 4. Настройка параметров (.env)

Создайте файл настроек из примера:

```bash
cp .env.example .env
```

В Windows (PowerShell):

```powershell
Copy-Item .env.example .env
```

Отредактируйте `.env`:

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `APP_PORT` | порт, на котором открывается интерфейс | `8080` |
| `POSTGRES_USER` | пользователь БД | `pentest` |
| `POSTGRES_PASSWORD` | пароль БД | `pentest` |
| `POSTGRES_DB` | имя БД | `pentest` |
| `JWT_SECRET` | ключ подписи сессий | шаблонное значение |
| `ADMIN_LOGIN` | логин первого администратора | `admin` |
| `ADMIN_PASSWORD` | пароль первого администратора | `admin` |

**Обязательно перед боевым использованием:**

1. Задайте длинный случайный `JWT_SECRET`. Сгенерировать значение:
   ```bash
   openssl rand -hex 32
   ```
   или в PowerShell:
   ```powershell
   -join ((1..64) | % { '{0:x}' -f (Get-Random -Max 16) })
   ```
2. Смените `POSTGRES_PASSWORD` и `ADMIN_PASSWORD`.

> `ADMIN_LOGIN` и `ADMIN_PASSWORD` используются только при первом запуске,
> когда в базе ещё нет такого пользователя. Позже пароль меняется в
> интерфейсе («Пользователи» → «Изменить»), а не в `.env`.
>
> `POSTGRES_*` применяются только при создании тома базы данных. Чтобы
> сменить пароль БД на работающей установке, смените его внутри PostgreSQL
> и затем в `.env`.
>
> Смена `JWT_SECRET` завершает все активные сессии: пользователям нужно
> войти заново.

## 5. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает 2–5 минут: скачиваются базовые образы и зависимости
Python. Проверьте, что все три сервиса запущены:

```bash
docker compose ps
```

Ожидаемый результат: `db` в состоянии `healthy`, `backend` и `frontend` в
состоянии `running`.

Проверьте API:

```bash
curl http://localhost:8080/api/health
# {"status":"ok"}
```

Откройте в браузере `http://<адрес-сервера>:8080` (на этом же компьютере —
http://localhost:8080) и войдите под `ADMIN_LOGIN` / `ADMIN_PASSWORD`.

## 6. Первоначальная настройка в интерфейсе

Выполняется администратором один раз.

1. **Смените пароль администратора.** «Пользователи» → строка `admin` →
   «Изменить» → «Новый пароль».
2. **Заполните реквизиты Исполнителя.** «Настройки» → «Реквизиты
   Исполнителя». Они попадут в раздел 1.6 каждого отчёта.
3. **Проверьте параметры отчёта.** «Настройки» → «Параметры отчёта»: строка
   «Уровень критичности по методике ФСТЭК» в карточке, таблица 3.2, текст
   грифа в колонтитуле.
4. **Проверьте справочники по умолчанию.** «Настройки» → «Справочники по
   умолчанию»: инструментарий, нарушители, интерфейсы, угрозы, коэффициенты
   ФСТЭК. Изменения применяются к проектам, созданным после сохранения.
   Чтобы обновить перечень угроз БДУ, скачайте thrlist.xlsx с bdu.fstec.ru
   и загрузите его в «Настройки» → «Перечень угроз БДУ ФСТЭК России».
5. **Создайте исполнителей.** «Пользователи» → «Новый пользователь», роль
   «Исполнитель». Заполните фамилию, имя, отчество (фамилия и имя
   обязательны) и должность. При обновлении с прежней версии ФИО
   существующих пользователей раскладывается на части автоматически;
   учётные записи с ФИО из одного слова (например, «Администратор»)
   дозаполните вручную.
6. **Создайте проект и назначьте исполнителей.** «Проекты» → «Новый проект»;
   в проекте вкладка «Доступ».

Порядок работы исполнителя:

1. Открыть проект и заполнить вкладки «Общие данные» (в том числе лист
   согласования) и «Границы (Прил. 1)».
2. На вкладках «Внешний пентест», «Внутренний пентест» и «Анализ
   защищенности веб-приложения» добавить уязвимости и заполнить карточки
   (для веб-приложений — также категорию OWASP Top 10). Оценки и риск
   пересчитываются при каждом изменении. На вкладке «Социотехническое
   тестирование» добавить сценарии с изображениями и целевую группу,
   отметить действия сотрудников.
3. Загрузить скриншоты в блоки «Изображения PoC» и «Изображения
   результатов» и указать подписи.
4. На вкладке «Итоги (1.4, 3)» проверить сводные таблицы и при
   необходимости вписать преимущества для таблиц 1.4.x.
5. Нажать «Скачать отчёт (.docx)». Сводные таблицы 1.4.x, 3.1 и 3.2
   формируются автоматически.
6. Кто и что менял в проекте, видно на вкладке «История», а также в
   строках «Добавил / Изменил» у проекта и в карточках уязвимостей.
7. Открыть отчёт в Word. На вопрос «Обновить поля в документе?» ответить
   «Да»: Word пересчитает оглавление и номера страниц.

## 7. Управление сервисами

| Действие | Команда |
|---|---|
| Остановить | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Перезапустить | `docker compose restart` |
| Остановить и удалить контейнеры (данные сохраняются) | `docker compose down` |
| Журнал всех сервисов | `docker compose logs -f` |
| Журнал API | `docker compose logs -f backend` |
| Состояние | `docker compose ps` |

Контейнеры запускаются с политикой `restart: unless-stopped`: после
перезагрузки сервера они поднимаются сами, если не были остановлены вручную.

> **Не выполняйте `docker compose down -v`**, если данные нужны: ключ `-v`
> удаляет тома с базой и скриншотами.

## 8. Обновление

1. Сделайте резервную копию (раздел 9).
2. Получите новую версию: `git pull` (или замените файлы приложения
   вручную). Файл `.env` не хранится в репозитории и сохраняется.
3. Пересоберите и перезапустите:
   ```bash
   docker compose up -d --build
   ```
4. Проверьте `docker compose ps` и вход в интерфейс.

Если менялся только интерфейс:

```bash
docker compose up -d --build frontend
```

### Миграции базы данных

Схема базы обновляется автоматически при старте контейнера `backend`
средствами Alembic:

- на чистой базе создаются все таблицы;
- на базе от предыдущей версии недостающие столбцы добавляются без потери
  данных;
- если база уже в актуальном состоянии, ничего не меняется.

Отдельных действий при обновлении не требуется. Миграции применяются в
каталоге `backend/migrations`. Проверить текущую ревизию базы:

```bash
docker compose exec backend alembic current
```

Применить миграции вручную (обычно не нужно — выполняется при старте):

```bash
docker compose exec backend alembic upgrade head
```

> Перед обновлением на продакшене всегда делайте резервную копию (раздел 9):
> миграции меняют структуру базы.

## 9. Резервное копирование и восстановление

Копировать нужно и базу данных, и скриншоты.

### Резервная копия (Linux)

```bash
mkdir -p backup
# база данных
docker compose exec -T db pg_dump -U pentest -d pentest -Fc > backup/db_$(date +%F).dump
# скриншоты
docker run --rm -v pentest-reports_uploads:/data -v "$PWD/backup":/backup alpine \
  tar czf /backup/uploads_$(date +%F).tar.gz -C /data .
```

### Резервная копия (Windows, PowerShell)

```powershell
New-Item -ItemType Directory -Force backup | Out-Null
$d = Get-Date -Format yyyy-MM-dd
docker compose exec -T db pg_dump -U pentest -d pentest -Fc -f /tmp/db.dump
docker compose cp db:/tmp/db.dump "backup/db_$d.dump"
docker run --rm -v pentest-reports_uploads:/data -v "${PWD}/backup:/backup" alpine `
  tar czf "/backup/uploads_$d.tar.gz" -C /data .
```

> В PowerShell не перенаправляйте вывод `pg_dump` через `>`: PowerShell
> меняет кодировку и портит двоичный файл. Поэтому дамп сначала пишется в
> контейнер, а потом копируется.

Если вы меняли `POSTGRES_USER` или `POSTGRES_DB`, подставьте свои значения
вместо `pentest`.

Для регулярного копирования добавьте команды в cron (Linux) или
Планировщик заданий (Windows) и храните копии вне сервера.

### Восстановление

```bash
docker compose stop backend
# база данных (существующие данные будут заменены)
docker compose cp backup/db_2026-10-26.dump db:/tmp/db.dump
docker compose exec -T db pg_restore -U pentest -d pentest --clean --if-exists /tmp/db.dump
# скриншоты
docker run --rm -v pentest-reports_uploads:/data -v "$PWD/backup":/backup alpine \
  sh -c "rm -rf /data/* && tar xzf /backup/uploads_2026-10-26.tar.gz -C /data"
docker compose start backend
```

## 10. Установка без доступа в интернет

Образы собираются на машине с интернетом и переносятся в закрытый контур.

На машине с интернетом (в каталоге приложения):

```bash
docker compose build
docker pull postgres:16-alpine
docker save -o pentest-images.tar \
  pentest-reports-backend pentest-reports-frontend postgres:16-alpine
```

Перенесите на целевой сервер файл `pentest-images.tar` и каталог приложения.
Затем на целевом сервере:

```bash
docker load -i pentest-images.tar
cp .env.example .env      # и отредактируйте
docker compose up -d      # без --build
```

> Имена собранных образов зависят от имени каталога. Уточните их командой
> `docker images` после `docker compose build`.

Интерфейс не загружает ничего из интернета. Ссылка на калькулятор FIRST в
карточке уязвимости — просто внешняя ссылка; в закрытом контуре она не
откроется, на работу приложения это не влияет.

## 11. Доступ по HTTPS

Отчёты содержат конфиденциальные сведения о найденных уязвимостях. Если к
приложению обращаются по сети, а не только с локального компьютера,
включите HTTPS.

Рекомендуемый способ — поставить перед приложением обратный прокси (nginx
на хосте, корпоративный балансировщик) с вашим сертификатом и проксировать
на `http://127.0.0.1:8080`. Пример для nginx на хосте:

```nginx
server {
    listen 443 ssl;
    server_name reports.example.local;

    ssl_certificate     /etc/ssl/certs/reports.crt;
    ssl_certificate_key /etc/ssl/private/reports.key;

    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 120s;
    }
}
```

Чтобы порт 8080 не был доступен из сети напрямую, привяжите его к локальному
адресу в `docker-compose.yml`:

```yaml
    ports:
      - "127.0.0.1:${APP_PORT:-8080}:80"
```

Дополнительно ограничьте доступ к серверу межсетевым экраном только
нужными подсетями.

## 12. Решение проблем

| Симптом | Причина и решение |
|---|---|
| `port is already allocated` при запуске | Порт 8080 занят. Укажите другой `APP_PORT` в `.env` и выполните `docker compose up -d`. |
| Страница не открывается | Проверьте `docker compose ps`. Если `frontend` не запущен — `docker compose logs frontend`. На сервере проверьте межсетевой экран. |
| Вход не работает, «Неверный логин или пароль» | Пароль из `.env` применяется только при первом запуске. Если пароль утерян — см. сброс ниже. |
| После входа сразу выбрасывает на страницу входа | Сменился `JWT_SECRET` или истёк срок сессии (12 часов). Войдите заново. |
| Ошибка 502 при работе | Не запущен или перезапускается `backend`: `docker compose logs backend`. Частая причина — неверный пароль БД после смены `POSTGRES_PASSWORD` на существующем томе. |
| `backend` не стартует, ошибка подключения к БД | Дождитесь статуса `healthy` у `db`. Если пароль в `.env` менялся после первого запуска, верните прежний или смените пароль в PostgreSQL. |
| Не загружается скриншот | Допустимые форматы: PNG, JPG, GIF, WEBP, BMP, размер до 25 МБ. Для больших файлов увеличьте `client_max_body_size` в `frontend/nginx.conf` и в обратном прокси. |
| Сборка падает на `pip install` | Нет доступа к PyPI. Настройте прокси для Docker или используйте раздел 10. |
| В отчёте пустые K/E/H и нет строки V | В карточке не выбраны все пять показателей ФСТЭК (K, L, P, E, H) или строка V отключена в «Настройках». |
| В оглавлении у всех пунктов страница «1» | Поля не обновлены. В Word: щёлкнуть по оглавлению → F9 → «обновить целиком» (или Ctrl+A, F9). В LibreOffice: «Сервис» → «Обновить» → «Обновить всё». |
| В отчёте нет балла CVSS | Вектор не задан или некорректен: ошибка показана под полем вектора в карточке. Нужен полный вектор CVSS 3.1 с восемью базовыми метриками. |

### Сброс пароля администратора

Если ни один администратор не может войти, назначьте новый пароль через
контейнер `backend`:

```bash
docker compose exec backend python -c "
from app.db import SessionLocal
from app.models import User
from app.security import hash_password
db = SessionLocal()
u = db.query(User).filter_by(login='admin').first()
u.password_hash = hash_password('НовыйПароль123'); u.is_active = True
db.commit(); print('пароль изменён')
"
```

Сразу после входа смените этот пароль в интерфейсе.

### Сбор сведений для обращения в поддержку

```bash
docker compose ps > diag.txt
docker compose logs --tail=300 >> diag.txt
```

Перед отправкой файла убедитесь, что в нём нет конфиденциальных данных.
